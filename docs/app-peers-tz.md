# ТЗ для приложения: пиры (нога 2)

Контракт сервера готов и задеплоен: ключ живёт на устройстве, адрес выдаёт api, права — по env.
Этот документ описывает, что должно делать приложение. Источник истины по ручкам —
`docs/api-peers.md`; здесь — поведение клиента.

Термины:

* **plan** — что куплено (`standard`, `lite`). В интерфейсе показываем `plan_title` («Standard»,
  **«Super Duper»** для `lite`), никогда не сырое значение.
* **env** — шард (инфраструктура, ёмкость). Юзеру не показывается никогда.
* **pool** — карточка локации («Нидерланды»). Показываем `pool_translation`, при отсутствии — `pool`.
* **peer** — туннель: ключ устройства + env + протокол + адрес `/32`.


## 0. Транспорт: AGW-конверт

Каждая клиентская ручка пиров — **POST с шифрованным телом**:

```json
{ "keyPayload": "<base64 RSA(aes_key,aes_iv,aes_salt)>",
  "apiPayload": "<base64 AES-256-CBC(JSON)>" }
```

Ответ — AES-256-CBC байты, расшифровываются тем же ключом. Клиент уже реализует это
для `/v1/config`; переиспользуется как есть, без изменений. Плейн-JSON api на этих
ручках не принимает и не возвращает — конверт не опционален.

Это не косметика: `subscription_id` и `peer_id` живут только в теле, поэтому не утекают
в access-логи прокси, в историю и в крэш-репорты.

---

## 1. Ключи и устройство

### 1.1. Пара ключей

* Одна X25519-пара на установку (`WireGuard`/`AmneziaWG` одинаково).
* Генерится **на устройстве** при первом запуске, до любой сетевой активности.
* Приватный ключ живёт в Keychain (iOS) / Keystore + EncryptedSharedPreferences (Android) / в
  `amnezia/` профиле (desktop). **Никогда** не уходит в сеть и не попадает в логи, отчёты, крэши.
* Публичный ключ (base64, 32 байта) — единственное, что отправляется в api.

### 1.2. `device_uid`

* UUID v4, генерится один раз на установку, хранится вместе с ключом.
* iOS: Keychain переживает переустановку — uid не пересоздаём.
* Android: `EncryptedSharedPreferences` + бэкап, иначе после переустановки это новое устройство.
* `device_name` — редактируемая строка («iPhone Ани», «Роутер дома»), по умолчанию модель.

### 1.3. `support_tag`

* Приходит от сервера в ответ на первый `POST /v1/peers` (`support_tag`).
* Показывается в экране «О приложении / Поддержка»: «Код для поддержки: 7K2M-9XQ4P».
* Не участвует ни в одном запросе — только читается юзером.

## 2. Активация

### 2.1. Флоу

1. Юзер вводит код → `POST /v1/activate` (новый флоу; старая ручка `/v1/key/activate` остаётся на
   время раскатки).
2. Ответ содержит подписку и, если сервер выдал доступ, `env` + `capacity`.
3. `503` (`no_live_shard` / `plan_not_configured`) → экран: «Сейчас нет доступных серверов.
   Напишите в поддержку — ключ не потрачен», с кнопкой «Повторить» и копированием `support_tag`,
   если он уже есть.

### 2.2. Легаси-юзер (обновление приложения)

Приложение уже имеет старый `.conf` с приватным ключом:

1. При старте: `POST /v1/locations` (конверт). Есть `access[]` → показываем карточки.
2. Нет ни одного пира для этого env → `POST /v1/peers` с **публичным ключом, выведенным из
   старого приватника** (приватник не меняется).
3. Новый `.conf` пишем рядом со старым, старый не удаляем до успешного рукопожатия.
4. Старые конфиги после перехода не работают (сервер их больше не отдаёт) — приложение это знает
   и не показывает их в списке.

## 3. Экран локаций

Источник: `POST /v1/locations` с телом `{ "subscription_id": "<uuid>" }` (AGW-конверт, как у
`/v1/services`: `subscription_id` в query не ходит).

```json
{
  "access": [
    { "env": "standard-eu", "plan": "standard", "plan_title": "Standard",
      "protos": ["amnezia_peer","wireguard_peer"],
      "expires_at": "2026-12-19T00:00:00Z", "traffic_limit": null, "used_bytes": 0 }
  ],
  "pools": [
    { "env": "standard-eu", "pool": "nl", "pool_translation": {"ru": "Нидерланды"},
      "proto": "amnezia_peer",
      "nodes": [ { "endpoint": "1.2.3.4:51820", "server_public_key": "…",
                   "mtu": 1280, "dns": ["1.1.1.1"], "keepalive": 25,
                   "obfuscation": { "jc": 4, "jmin": 40, "jmax": 70,
                                    "s1": 30, "s2": 60, "h1": "…", "h2": "…", "h3": "…", "h4": "…" } } ] }
  ]
}
```

Правила отображения:

* одна карточка = один `pool` (плюс `plan_title` как заголовок группы, если планов несколько);
* внутри карточки — «N серверов» (число `nodes`), выбор конкретной ноды — прерогатива клиента:
  строим конфиг на первую, при неудаче — следующую, либо балансируем как в старом флоу;
* параметры `server_public_key` / `obfuscation` / `mtu` / `dns` берутся **из карточки**, а не из
  общих настроек: у разных пулов они разные;
* пустая карточка (нет живых нод) не приходит вообще — показывать нечего;
* `used_bytes` и `traffic_limit` — прогресс квоты; при `traffic_limit = null` показываем только
  расход, без полосы.

## 4. Создание туннеля

`POST /v1/peers`

```json
{ "subscription_id": "…", "device_uid": "…", "device_name": "iPhone",
  "env": "standard-eu", "proto": "amnezia_peer", "public_key": "<base64>", "label": null }
```

Когда вызывать: **лениво**, в момент «Подключиться», а не при старте — иначе лимит 5 забьётся
мусорными env, куда юзер ни разу не ходил.

Ответ:

```json
{ "peer": { "peer_id": "…", "device_id": "…", "env": "standard-eu", "proto": "amnezia_peer",
            "address": "10.88.0.2/32", "label": null, "created_at": "…" },
  "support_tag": "7K2M-9XQ4P",
  "pools": [ /* то же, что в /v1/locations, уже отфильтровано по env */ ] }
```

Конфиг собирается **из этого ответа**, без второго запроса: между «пир создан» и «конфиг собран»
не должно быть окна.

Идемпотентность: тот же `public_key` в том же env → `200` и тот же пир. Приложение может смело
повторять запрос при таймауте.

---

## 5. Сборка конфига

### AmneziaWG (`proto = "amnezia_peer"`)

```ini
[Interface]
PrivateKey = <локальный приватный>
Address    = <peer.address>
DNS        = <nodes[0].dns через запятую>
MTU        = <nodes[0].mtu>
Jc = <obfuscation.jc>
Jmin = <obfuscation.jmin>
Jmax = <obfuscation.jmax>
S1 = <obfuscation.s1>
S2 = <obfuscation.s2>
<H1..H4 — строковые, как пришли>

[Peer]
PublicKey = <nodes[i].server_public_key>
Endpoint  = <nodes[i].endpoint>
AllowedIPs = 0.0.0.0/0, ::/0
PersistentKeepalive = <keepalive или 25>
```

### WireGuard (`proto = "wireguard_peer"`)

То же без строк `Jc/Jmin/Jmax/S1/S2/H1..H4` (чистый WG). MTU по умолчанию 1420, если не пришёл.

Одно устройство — один конфиг на карточку; `Address` и `PrivateKey` у всех карточек одного env
одинаковые, различаются только `Endpoint`/`PublicKey`/обфускация.

## 6. Состояния и ошибки

| ответ | что показываем |
|---|---|
| `402 quota_exhausted` | «Трафик закончился» + кнопка «Пополнить» |
| `402 grant_expired` | «Срок доступа истёк» + «Продлить» |
| `403 no_grant` / `proto_not_granted` | «Этот сервер не входит в вашу подписку» (не показывать env) |
| `403 env_not_served` | «Локация временно недоступна» |
| `409 device_limit` | «На этом устройстве уже 5 туннелей — удалите лишний» |
| `409 subscription_limit` | «Достигнут лимит туннелей» + поддержка |
| `409 key_taken` | Считать это «пир уже есть»: перейти к `POST /v1/peers/list` |
| `503 no_free_address` | «Нет свободных мест в локации» + поддержка |
| сеть/таймаут | повтор `POST /v1/peers` (идемпотентно), 3 попытки с бэкоффом |

---

## 7. «Перезапросить конфиг»

Кнопка в настройках туннеля и автотриггер при ошибке рукопожатия:

1. `POST /v1/peers/list` с `{subscription_id, device_uid}`;
2. пир живой → берём `address` и пересобираем `.conf` из `POST /v1/locations`;
3. пира нет или он `revoked` → `POST /v1/peers` с **тем же** публичным ключом → новый адрес,
   `.conf` перезаписывается (приватник тот же);
4. `revoke_reason` показываем человеческим текстом:

| `revoke_reason` | текст |
|---|---|
| `expired` | «Срок доступа истёк» |
| `quota` | «Трафик исчерпан» |
| `user` | «Туннель удалён» |
| `subscription_ended` | «Подписка завершена» |

---

## 8. Устройства и каналы

* `POST /v1/devices/list` (`{subscription_id}`) → список устройств с `support_tag` и числом
  туннелей; переименование — `POST /v1/devices/update` (`{subscription_id, device_id, device_name}`),
  удаление — `POST /v1/devices/delete` (`{subscription_id, device_id}`, снимает все туннели).
* Роутер/Linux: несколько туннелей на одном устройстве. Второй канал **в том же env** требует
  своего `public_key` (ядро держит пиров по ключу) и `label` («ch2»); в разных env — один ключ.
* Лимиты: 5 туннелей на устройство, 50 на подписку. Числа приходят только как ошибки `409`, в UI
  показываем формулировки из таблицы выше.

---

## 9. Приватность и телеметрия

* Публичный ключ, `device_uid`, `device_name` — можно отправлять.
* Приватный ключ, содержимое `.conf`, IP-адреса посещённых сайтов — нельзя, ни в аналитику, ни в
  крэши.
* `support_tag` — идентификатор для поддержки, не секрет, но и не для публичных экранов.

---

## 10. Критерии приёмки

1. Новый юзер: код → `/v1/activate` → карточки локаций → «Подключиться» → рукопожатие < 2 с.
2. Приватный ключ не встречается ни в одном запросе (проверка прокси/логов), и в приложении его
   нельзя увидеть в открытом виде (кроме экспорта «показать конфиг», если такая функция есть).
3. Повторный `POST /v1/peers` при таймауте не создаёт второй туннель.
4. Переключение карточек NL ↔ DE внутри env не создаёт новый пир и не тратит лимит.
5. Смена `device_name` не влияет на работу туннеля.
6. Просрочка: туннель перестаёт подниматься, экран говорит «Срок доступа истёк», после оплаты
   кнопка «Перезапросить конфиг» возвращает доступ без новых ключей.
7. Исчерпанная квота (`lite`/Super Duper): туннель снят, экран «Трафик исчерпан», `used_bytes`
   не сбрасывается после пересоздания пира.
8. Легаси-юзер после обновления: приложение продолжает работать со своим старым приватным ключом,
   новый `.conf` собирается без участия юзера.
9. `support_tag` виден в приложении и по нему поддержка находит устройство.
10. Ни одного экрана, где юзеру показывается `env` или сырое имя плана (`lite`).
