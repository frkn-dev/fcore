# Веса адресов пула (`node_weights`) — контракт api → клиент

Статус: api отдаёт поле с 0.6.117. Клиент (Dopamine) его пока **не читает** —
до клиентской части поведение прежнее.

## Что отдаёт api

Пул остаётся одной записью `GatewayConnection`; точек входа в ней N, и у каждой
свой вес:

```json
{
  "connection_uuid": "…",
  "connection_label": "Russia · AmneziaWG",
  "pool": "Russia",
  "node_ips":   ["93.89.220.48", "93.89.220.49", "77.221.152.88"],
  "node_ports": {"93.89.220.48": 443, "93.89.220.49": 443, "77.221.152.88": 8443},
  "node_weights": {"93.89.220.48": 75, "93.89.220.49": 25, "77.221.152.88": 100},
  "weight": 100,
  "config_rev": "…"
}
```

Правила:

- `node_weights` — карта «адрес → вес». Ключи всегда совпадают с `node_ips`
  и `node_ports`: адрес без веса в карте не появится, адрес из карты не
  потеряется.
- Вес по умолчанию — **100** (обычная нода). Значения могут повторяться.
  Вес 0 или меньше трактуется как «не задан», то есть 100.
- Одиночная нода без весов поля не несёт (нет смысла). С несколькими
  адресами или с явными весами — несёт.
- `weight` (число) — **легаси** для старых клиентов: они требуют числовое поле
  и без него выбрасывают сервер целиком (`client/mozilla/models/server.cpp`).
  Значение = максимум по адресам. Новой логике читать его не нужно.

Поле появляется только при наличии весов/нескольких адресов, поэтому старые
сборки api и клиенты его просто не видят — обратная совместимость сохраняется.

## Откуда вес берётся

В конфиге ноды (`/opt/fnode/config.toml`), ключ — адрес из `node_ips`:

```toml
[node]
node_ips = ["93.89.220.48", "93.89.220.49"]
node_weights = { "93.89.220.48" = 75, "93.89.220.49" = 25 }
```

fnode присылает карту при регистрации, api хранит её в `nodes.node_weights`
(JSONB) и отдаёт клиентам. Нода со старой сборкой (< 0.6.117) карту не шлёт —
её адреса весят 100.

## Что должен делать клиент

1. Разбирать `node_weights` рядом с `node_ports` в `servers_model.cpp`
   (хелпер по образцу `portForNodeIp`: `weightForNodeIp(ip)` → вес или 100).
2. При выборе адреса пула — **взвешенный случайный выбор** по весам только
   среди адресов, прошедших проверку доступности: `P(ip) = w(ip) / Σw`.
   Сортировать по весу нельзя: это доли, а не приоритет.
3. Ошибка/недоступность адреса — исключить его из набора и перенормировать
   сумму; когда набор опустеет, сбросить исключения и начать заново.
4. Пинг остаётся проверкой живости, а не множителем: медленный, но «тяжёлый»
   адрес должен получать свою долю (иначе он никогда не разгрузится).
5. Если `node_weights` нет вовсе — равномерный выбор, как сейчас.

## Проверка

- `curl` карточки пула на проде: ключи `node_weights` == ключи `node_ports`.
- Пул из двух нод 75/25 → за 100 подключений примерно 75/25.
- Нода без веса → 100 (равная доля с «обычными»).
