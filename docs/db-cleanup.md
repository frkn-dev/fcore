# Чистка БД: план

Срез продакшена 20.11.2026, после `0022`. Миграция удаления — `deploy/migrations/0023_drop_unused.sql`, **не накатана**, применяется руками.

## Сносим (мёртвое, кода нет)

| объект | строк | почему |
|---|---|---|
| `node_metrics` | 0 | ни одного `INSERT` в коде. Метрики нод живут в rkyv-снапшоте `metrics.snapshot_path`, не в Postgres |
| `node_metrics_1m` (view) | 0 | роллап над пустой таблицей |
| `grafana_metrics` (view) | 0 | то же; проверить, не читает ли внешняя Grafana |
| `digest_runs` | 4 | сводки уехали в mrkting (0.6.139), ни планировщика, ни записи в api не осталось |

Порядок: вьюхи → таблицы, одной транзакцией. Перед накаткой — `SELECT count(*)` и `pg_depend`.

## Ждёт решения

| объект | проблема | варианты |
|---|---|---|
| `pools` | 0 строк: ни одна нода не объявляет `pool`. `shard_overview.pools` поэтому пуст у всех 56 шардов | (а) вернуть `pool` в конфиги нод; (б) снести таблицу и колонку из вьюхи — карточки и так строятся по живым нодам |
| `client_reports` | путь записи есть (`postgres/report.rs:516`), строк 0 — приложение отчёты не шлёт | проверить клиент; если путь мёртв — снести вместе с ручкой |
| `connection_attempts` | то же: писатель есть (`report.rs:585`), строк 0 | то же |

## Оставляем (пусто по делу)

`subscription_access`, `peers`, `peer_traffic`, `devices` — фича ещё не включена юзерам.
`iap_transactions` — App Store только в TestFlight.
`activation_failures` — очередь «оплачено, но не выдано», пуста = хорошо.
`subscription_limits`, `subscription_alert_chats` — overrides/чаты никто не настраивал.
`block_observations` — пишет сервис вне этого репо, api только чистит.

## Отдельно: снапшот метрик

`/opt/api/snapshots/metrics.*` — ~1.78 ГБ (6 партов), переписывается целиком на каждый `snapshot_interval`. Полезное в нём — серии метрик нод, которые ничем не читаются, потому что `node_metrics` пуст, а графики никто не строит. Долговечный учёт трафика от него не зависит: `connection_traffic`/`peer_traffic` апсертят дельты, `subscription_traffic` считает лимиты.

Кандидаты: выключить сейв или срезать retention точек. Требует разбора содержимого партов (скрипт по `MetricStorageSnapshot`), поэтому — отдельной задачей.
