# Lite-ключ — обработка в приложении

Lite-ключ — новый тип ключа: покупаешь не дни, а **объём трафика навсегда** (пока не израсходуешь). Подписка живёт, пока есть байты на балансе; `expires_at` не задаётся.

Внешне ключ неотличим от обычного — определить можно только ответом `/key/validate` по полю `kind: "lite"`. Полная цепочка ключа — в [key-activation-app.md](key-activation-app.md); здесь — только то, что отличается для lite.

Base URL: `https://api.frkn.org`. Все ручки публичные, auth-токен не требуется.

## Что отвечает `/key/validate` для lite

```json
{
  "status": 200,
  "message": "Key is valid",
  "response": {
    "id": "a9e75125-...",
    "instance": {
      "Key": {
        "code": "ALPMQ-6TSD2-DUMUS-LJYAA-AAABP-ETLFP-A",
        "days": 0,
        "activated": false,
        "kind": "lite",
        "traffic_gib": 5,
        "traffic_bytes": 5368709120,
        "subscription_id": null
      }
    }
  }
}
```

| Поле | Для lite | Что с ним делать |
|---|---|---|
| `days` | `0` | Не показывать — это не время |
| `kind` | `"lite"` | Включить lite-флоу |
| `traffic_gib` | `5` | «**5 ГБ** трафика навсегда» |
| `traffic_bytes` | `5368709120` | Точное число байт для расчёта прогресса, если хочешь показать шкалу до подтверждения |

При показе пользователю: **«N ГБ трафика»** (без слова «навсегда» — пользователи пугаются).

## Активация lite

`POST /key/activate`:

```json
{
  "code": "ALPMQ-6TSD2-DUMUS-LJYAA-AAABP-ETLFP-A",
  "subscription_id": null,
  "email": null
}
```

- `email` опционален. Если передал — к нему привязывается аккаунт: придёт письмо «ключ FRKN», и когда трафик кончится — уведомление. Без email всё работает, но восстановление/уведомления по почте не придут. Юзер может привязать email позже в ЛК.
- `subscription_id` опционален. Для lite новых не передавай — пусть создастся отдельная подписка; в существующую тоже можно (докупить трафик к имеющемуся ключу).

Успех 200: `message = "Key {id} activated"`, `response.instance.Key.subscription_id` — id подписки. Дальше идём в `/subscription/{id}` (см. ниже).

## Статус lite-подписки: `GET /subscription/{id}`

Ключевые поля:

```json
{
  "id": "61da5a16-0346-4c09-9239-38f943d6c088",
  "expires": null,
  "days": 0,
  "plan_kind": "lite",
  "limit_bytes": 5368709120,
  "used_bytes": 102400,
  "remaining_bytes": 5368606720,
  "downlink": 102400,
  "uplink": 0,
  "daily_downlink": 102400,
  "daily_uplink": 0,
  "monthly_downlink": 102400,
  "monthly_uplink": 0,
  "connections": [...],
  "ref_code": "38f943d6c088"
}
```

| Поле | Что делать в UI |
|---|---|
| `plan_kind === "lite"` | Этот ветка UI — traffic-first, без таймера |
| `expires` | `null` — **никогда не показывай «X дней»**, «∞» или скрывай блок expiry |
| `days` | `0` — игнор |
| `limit_bytes` / `used_bytes` / `remaining_bytes` | **Главный счётчик.** Показывай шкалу: «1.2 ГБ из 5 ГБ» или «осталось 3.8 ГБ». Используй `formatBytes(bytes)` (KiB/MiB/GiB) |
| `downlink`/`uplink` | Накопительный трафик сессии (как у `standard`) |
| `daily_*` / `monthly_*` | Если есть — показывай отдельной строкой «сегодня: X, за месяц: Y» |
| `connections` | Список устройств — стандартное поведение |
| `ref_code` | Для шаринга «приведи друга» |

### Состояния lite-подписки

| Состояние | Условие | UI |
|---|---|---|
| Active | `remaining_bytes > 0` | Зелёный «Активна», шкала трафика |
| Exhausted | `used_bytes >= limit_bytes` | Красный «Трафик кончился», кнопка «Докупить трафик» (НЕ «Продлить подписку» — у lite нет срока) |
| No connection | `connections.length === 0` | «Добавьте устройство» (как у standard) |

## Докупка трафика: `POST /payment/platega/topup/create`

lite-подписке трафик докупается через платёжный шлюз (Platega сейчас, Планта — когда вайтлистнут вебхук):

```
POST /payment/platega/topup/create
{
  "subscription_id": "<uuid>",
  "gb": 5
}
```

`gb` — пакеты 1/5/10/50 (как в продаже). Ответ 200: `{transactionId, url, status:"PENDING", expiresIn, rate, traceId}`. Открой `url` в браузере/CustomTabs, после оплаты webhook прибавит трафик, баланс увеличится на `gb × 1 GiB`. Список подписки обнови.

> **Не пытайся «активировать новый ключ для top-up»** — это работает, но медленнее и обходится через тот же сценарий. Докупка через шлюз дешевле (нет комиссии Platega на покупку + зачисление атомарно).

## Когда трафик кончился

- Соединения пользователя **останавливаются** — VPN на паузе.
- Backend: `enforce_traffic_limits` каждые 5 минут удаляет connections у тех, у кого `used_bytes >= limit_bytes`. После удаления новый коннект авто-создаётся только если трафик пополнился.
- Email-уведомление (если email привязан): «Трафик кончился» + кнопка «Докупить» (письмо в mrkting).
- В приложении: показывай красный статус + баннер «Трафик кончился, докупи N ГБ» с кнопкой → открывает `pay` flow с `ref_code` подписки (чтобы юзер сразу видел «Докупить трафик», а не «Купить ключ»).
- НЕ предлагай «продлить подписку» — это для standard, у lite нет срока. Слово «продли» в любом контексте для lite вводит юзера в заблуждение.

## Email (опциональный)

Если юзер передал email при активации:
- Сразу приходит письмо «Твой ключ FRKN» (mrkting). Если нужно — игнор.
- Через 3 дня / 24ч / 6ч **до любого «expiry» не придёт ничего** — у lite нет expiry. Email-цепочка отключена.
- Когда трафик кончится — уведомление «Трафик закончился» (mrkting `send_lite_event_email`).
- После top-up — уведомление «Баланс трафика пополнен».

Если email не передан при активации — всё работает без уведомлений. Юзер может привязать email позже в ЛК через `POST /account` (см. [API.md](API.md)).

## Edge cases

| Ситуация | Поведение |
|---|---|
| Пользователь активирует lite-ключ, не активировав ранее standard | Создаётся новая подписка с traffic_gib=0 (только что купленный трафик добавляется при активации? — нет, трафик добавляется через отдельный top-up flow, ключ **сразу содержит трафик в `limit_bytes`**). Короче: при активации lite-ключа новая подписка сразу создаётся с балансом = `traffic_gib` ключа. Используй `limit_bytes` как «всего куплено», `used_bytes` как «потрачено» |
| Пользователь активирует второй lite-ключ | Создаётся ещё одна подписка (можно — это параллельные счёта). Приложение должно показать обе подписки в списке. `reconcile_enabled_connections` ничего с этим не делает (он только создаёт отсутствующие `(env,proto)` для **активной** подписки, не множит их) |
| Пользователь активирует lite-ключ, передав `subscription_id` старой подписки | Трафик добавляется к существующей — НЕ создаёт новую. `limit_bytes` увеличивается на `traffic_gib` ключа (т.е. `1 + 5 → limit_bytes = 6 GiB`). Если подписка была standard и истекла — трафик прибавится к оставшемуся балансу |
| Пользователь активирует lite-ключ на активной standard-подписке | Трафик добавится, но `traffic_mode_enabled` блокирует трату на незавершённой по времени подписке (enforce_traffic_limits игнорирует незавершённые). На практике: баланс растёт, но списывать не будет пока standard не истечёт |
| `used_bytes > limit_bytes` | Технически возможно из-за race между замерами. Не ломай UI: показывай «100% использовано», отключай VPN |

## Чек-лист для приложения

- [ ] Парсинг ключа принимает оба формата (см. [key-activation-app.md](key-activation-app.md))
- [ ] После `GET /key/validate` если `kind === "lite"` — экран «**N ГБ** трафика» (не показывать «∞», «навсегда», «дней»)
- [ ] После активации смотри `limit_bytes` и показывай шкалу трафика (KiB / MiB / GiB)
- [ ] Если email не указан — не настаивай, не блокируй UI, но дай возможность привязать позже (открыть frkn.org/subscription/?id=…)
- [ ] Никогда не показывай «Подписка истекает через X дней» для lite
- [ ] Если `used_bytes >= limit_bytes` — красный + кнопка «Докупить трафик» (НЕ «Продлить»)
- [ ] Top-up через `POST /payment/platega/topup/create { subscription_id, gb }` (1/5/10/50 ГБ)
- [ ] После top-up обнови баланс (`limit_bytes`, `remaining_bytes`) — polling или pull-to-refresh
- [ ] Не пытайся валидировать ключ локально по формату — только `/key/validate`

## Сводка эндпоинтов для lite

| Действие | Метод | Путь | Тело |
|---|---|---|---|
| Проверить ключ | `GET` | `/key/validate?key=<code>` | — |
| Активировать | `POST` | `/key/activate` | `{ code, subscription_id?, email? }` |
| Статус | `GET` | `/subscription/<id>` | — |
| Докупить трафик | `POST` | `/payment/platega/topup/create` | `{ subscription_id, gb }` |
| Привязать email | `POST` | `/account` | `{ email, subscription_id }` |

Все ручки публичные. Auth-токен не нужен (для mgmt-операций есть отдельный Bearer — см. [API.md](API.md)).
