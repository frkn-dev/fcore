# `POST /v1/nodes/load` — загрузка нод

Клиент спрашивает загрузку адресов на момент подключения. Отдельная ручка, а не поле
в `/v1/config`: конфиг тянется раз в несколько часов и может зависнуть, а загрузка нужна
именно сейчас.

## Запрос

Шифрованный конверт gateway, как у `/v1/services` (`keyPayload` / `apiPayload`).

```json
{
  "auth_data": { "id": "<subscription uuid>" },
  "node_ids": ["<node uuid>", "..."]
}
```

- `node_ids` — до **50** штук, дубликаты и невалидные uuid отбрасываются молча;
- авторизация — `auth_data.id` подписки, как в `/v1/services` (отдельного секрета нет);
- не чаще **одного запроса в 15 секунд** на подписку, иначе `429`.

## Ответ

```json
{
  "at": "2026-11-05T21:59:12.345+00:00",
  "load": { "6f9c…": 0.42, "1a2b…": 1.0 }
}
```

- `at` — момент расчёта (RFC3339), чтобы клиент сам решал, устарели ли данные;
- `load` — доля занятости `0.0 … 1.0`;
- **нет ключа = нет данных.** Это не ноль: `0.0` читается как «нода свободна» и
  перетянет на неё весь трафик. Клиент обязан трактовать отсутствие ключа как
  «нет данных, выбираем по весам».

## Формула

```
bandwidth_util = (rx_bps + tx_bps по всем интерфейсам) / max_bandwidth_bps ноды
conn_util      = active_conns (сумма net.inbound.*.connections) / node_load_conn_capacity
cpu_util       = среднее sys.cpu.* / 100

mixed = 0.6 * conn_util + 0.4 * cpu_util
load  = clamp(max(bandwidth_util, mixed), 0.0, 1.0)
load  = 1.0, если load >= node_load_threshold
```

- все значения — **среднее за 60 с**; серия без свежих точек не участвует вообще;
- отсутствующие слагаемые пропускаются (нода без CPU-метрик всё равно получает оценку
  по полосе), но если данных нет совсем — ключа в ответе нет;
- `node_load_threshold` (по умолчанию `0.85`) делает перегруз двоичным: клиенту отдаётся
  `1.0`, а не «0.87», которое он проигнорирует.

## Настройки api

```toml
[service]
# Вместимость соединений на ноду: ноды пока не сообщают свой лимит,
# поэтому одно число на всю стаю.
node_load_conn_capacity = 300
node_load_threshold = 0.85
```

## Что клиенту делать с этим

```
w_eff = max(w * (1 - load), w * 0.15)
P     = w_eff / Σ w_eff
```

- таймаут запроса 800 мс, кэш ответа 30 с, данные старше 60 с игнорируются;
- `404` (старый api), таймаут, `429` — тихий откат к чистым весам из `/v1/services`;
- веса приходят per-address в `node_weights` (см. `docs/pool-weights.md`), ключи
  `node_weights` и `node_ports` совпадают всегда.

## Что не сделано

- **per-node `conn_capacity`**: в конфиге ноды такого поля нет, число берётся из
  конфига api (`node_load_conn_capacity`). Когда появится поле в `[node]`, его стоит
  предпочитать общему значению.
- **qdisc-задержки и потери** в формуле не участвуют — только полоса, соединения и CPU.
