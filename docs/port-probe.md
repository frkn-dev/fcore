# Port probe — проверка, какие порты ноды доходят до клиента

Фича поддержки: юзер по просьбе саппорта заходит в диагностику и нажимает «Find port».
Нода на время теста поднимает N портов, ловит пакеты **с его IP** и отдаёт отчёт
«порт открыт / молчит». Нужна для случая «у оператора зарезаны порты»: сейчас мы
перебираем порты руками через `UPDATE inbounds` + iptables (так разбирались с KG).

Три участника: **api** (заказ и хранение), **fnode** (порты и замер), **клиент** (кнопка,
спека отдельно). Ниже — контракт бекенда.

## Как сигнал доходит до ноды

Ноды сегодня только **ходят в api** (register, metrics, snapshot, watchcat).
Канал api → нода есть только ZMQ-`Message`, а он `rkyv`-структура под менеджмент
коннектов (`conn_id`, `action`, `tag`, …): добавить туда поле — сломать все ноды
на старых бинарях.

Поэтому **поллинг по HTTP**: fnode раз в 5 с спрашивает
`GET /v1/node/port-test` и, если тест есть, забирает его и работает. Старая нода
эту ручку не знает — просто не вызывает; новый api живёт со старыми нодами как
раньше. Ответ 204 = «тестов нет», никакой нагрузки сверх одного пустого запроса
в 5 секунд.

## Схема (миграция `deploy/migrations/0017_port_tests.sql`)

```sql
create table if not exists port_tests (
    id              uuid primary key default gen_random_uuid(),
    node_id         uuid not null references nodes(id) on delete cascade,
    subscription_id uuid,                 -- чей это тест: в config попадёт только ему
    support_tag     uuid,                 -- installation uuid из отчётов, для дашборда
    protocol        text not null,        -- 'udp' | 'tcp'
    ports           int[] not null,
    client_ip       inet,                 -- считать пакеты только с этого адреса
    window_secs     int not null default 60,
    status          text not null default 'pending',  -- pending|running|done|expired|failed
    requested_by    text,                 -- кто из саппорта нажал
    created_at      timestamptz not null default now(),
    started_at      timestamptz,
    finished_at     timestamptz,
    result          jsonb                 -- см. «Отчёт ноды»
);
create index if not exists port_tests_pending_idx on port_tests (node_id, status);
```

`status` меняет только api: `pending` → `running` (нода забрала) → `done`/`failed`
(нода отчиталась). `expired` ставит фоновый таймер: тест, который никто не забрал
за 5 минут, или `running` дольше `window_secs + 60`.

## Ручки

### `POST /v1/admin/nodes/{node_uuid}/port-test` — заказать тест

Авторизация: service/admin (как остальные `/v1/admin/*`).

```json
{
  "protocol": "udp",
  "subscription_id": "72483aa3-…",   // опционально, но с ним тест увидит только этот клиент
  "support_tag": "023d804b-…",       // опционально
  "client_ip": "10.140.184.183",     // опционально: считать только этот источник
  "window_secs": 60,
  "ports": [2083, 2087, 2096, 1194]  // опционально; без него — дефолтный список
}
```

Ответ `201`:

```json
{"id": "…", "ports": [2083, 2087, 2096, 1194], "protocol": "udp",
 "window_secs": 60, "expires_at": "2026-11-09T15:20:00Z"}
```

Правила: `protocol` только `udp`/`tcp`; `ports` ≤ 64 и каждый 1..65535;
`window_secs` 10..300; на ноде одновременно не больше одного `pending`/`running`
теста (иначе `409 test_in_progress`).

Дефолтный список (общий для udp и tcp, кроме занятых на ноде — их нода пропускает
и помечает `busy`): `2083, 2087, 2096, 2053, 2052, 2082, 2086, 1194, 500, 4500,
1701, 3478, 5349, 8080, 8443, 8000, 9000, 9443, 10000, 1935, 8444, 2095`.

### `GET /v1/node/port-test` — нода забирает тест

Авторизация: node token. Одна ручка на ноду (нода знает себя по токену).
`200` — тело теста, `204` — тестов нет. При выдаче api атомарно ставит
`status='running', started_at=now()`.

```json
{"id": "…", "protocol": "udp", "ports": [2083, 2087],
 "client_ip": "10.140.184.183", "window_secs": 60}
```

### `POST /v1/node/port-test/{id}/result` — нода отчитывается

```json
{
  "status": "done",
  "started_at": "2026-11-09T15:10:00Z",
  "finished_at": "2026-11-09T15:11:05Z",
  "ports": [
    {"port": 2083, "state": "open",   "hits": 3, "first_at": "2026-11-09T15:10:12Z", "src_ip": "1.2.3.4"},
    {"port": 2087, "state": "silent", "hits": 0},
    {"port": 1194, "state": "busy",   "hits": 0}
  ]
}
```

`state`: `open` (пакеты пришли), `silent` (не пришло ничего), `busy` (порт был занят
чем-то другим и его пропустили), `error` (не удалось поднять сокет).

### `GET /v1/admin/port-tests/{id}` — забрать результат

```json
{"id": "…", "node": "kg.frkn.org", "protocol": "udp", "status": "done",
 "ports": [...], "result": {"ports": [...]}, "created_at": "…", "finished_at": "…"}
```

Плюс `GET /v1/admin/nodes/{uuid}/port-tests?limit=10` — история по ноде.
Дашборд читает эти две ручки; сегодняшняя ручная возня (`UPDATE inbounds`, iptables)
заменяется одним «переключить advertised-порт» (отдельная админ-ручка, следующий шаг).

## Что делает fnode

Новый модуль `src/bin/node/port_probe.rs` + таск в `node::run`:

- раз в 5 с `GET /v1/node/port-test`; при `204` спит дальше;
- на `200`: поднимает сокеты **на тех портах, что прислал api**, на `0.0.0.0`
  (udp — `UdpSocket`, tcp — `TcpListener`), кроме занятых (их `bind` падает → `busy`);
- **udp**: читает датаграммы, помнит `src_ip`/`first_seen`/`count`, отвечает
  `FRKN-PORT-OK <port>\n` на адрес источника — по времени до ответа клиент считает RTT;
- **tcp**: `accept` → записать `FRKN-PORT-OK <port>\n` → закрыть;
- если в тесте есть `client_ip` — считает только пакеты с этого адреса
  (остальное игнорирует, чтобы сканеры не портили отчёт);
- работает `window_secs`, после чего закрывает всё (в т.ч. по `Drop`/таймауту) и
  `POST`-ит результат;
- в лог: `port_probe: started id=… ports=8 window=60s` и
  `port_probe: done id=… open=3 silent=9 busy=2`;
- ошибки не роняют ноду: неудачный тест = `status: "failed"` в отчёте.

Порты не нужно открывать в фаерволе: `INPUT` на нодах в `ACCEPT`, `bind` открывает
порт сам. Если на ноде появятся nft-правила — добавить разрешение для тестового окна
(сейчас на kg.frkn.org правил `INPUT` нет, проверено).

Ограничения: ≤ 64 порта, окно ≤ 300 с, один тест за раз, всё в отдельной таске с
таймаутом, чтобы зависший тест не держал сокеты.

## Как это увидит клиент (контракт, спеку кнопки делаем отдельно)

Если у теста есть `subscription_id`, то в `/v1/config` этой подписки появляется
необязательный блок (в чужих конфигах его нет):

```json
"port_test": {
  "id": "…", "protocol": "udp", "ports": [2083, 2087],
  "expires_at": "2026-11-09T15:20:00Z"
}
```

Клиент пробует эти порты (реальный handshake/подключение, а не ICMP), показывает
`open / silent` и присылает результат; сервер уже знает свою половину и видит
расхождение: «клиент говорит open, нода не видела пакетов» = асимметрия/блокировка
на обратном пути.

## Чего в этой версии нет (осознанно)

- **Автопереключения порта**: тест только измеряет. Менять advertised-порт ноды
  пока руками/админ-ручкой — автоматику добавим, когда увидим, что фича работает.
- **Постоянного набора альтернативных портов** (мой ручной iptables REDIRECT на kg
  снимается после теста): v2 — nft-сет + редирект на awg-порт, тогда выбранный порт
  работает без переноса интерфейса.
- **ICMP/UDP-эха без протокола**: слушаем только свои порты и отвечаем своей строкой.

## План работ

1. Миграция `0017` + `postgres/port_tests.rs` (create/get/claim/finish/expire).
2. api: 4 ручки + фоновый таймер истечения + `port_test` в `/v1/config` (фильтр по `subscription_id`).
3. fnode: `port_probe.rs` + таск в `node::run` + тест на локальном сокете.
4. Дашборд: экран теста (отдельно, после 1–3).
