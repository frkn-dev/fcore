# После полной миграции на пиры: что выключать и что удалять

Документ для момента, когда **все живые подписки уже на грантах** и старый флоу больше не получает
трафика. Он отвечает на два вопроса: что нельзя удалять никогда (потому что нужно другим
протоколам) и что можно снести без сожалений, в каком порядке и по каким проверкам.

Главное правило: **`connections` не исчезает.** Vless и Hysteria2 остаются на старой схеме
(серверный ключ в конфиге), а гранты их только разрешают. Поэтому «удалить v1» = удалить
статические WG/AWG и каталог продуктов, а не весь слой коннектов.

---

## 0. Проверки перед первым шагом

Не начинать, пока все четыре не выполнены:

```sql
-- 1. подписок без грантов нет (иначе кто-то останется без доступа)
SELECT count(*) FROM subscriptions s
 WHERE NOT s.is_deleted
   AND NOT EXISTS (SELECT 1 FROM subscription_access a
                    WHERE a.subscription_id = s.id AND a.revoked_at IS NULL);
-- ожидается 0

-- 2. активаций через старую ручку нет за последние сутки (лог api)
--    grep '/v1/key/activate' — должно быть пусто

-- 3. живых статических WG/AWG коннектов нет
SELECT env, proto, count(*) FROM connections
 WHERE NOT is_deleted
   AND proto IN ('wireguard','amnezia_wg','amnezia_wg_mobile')
 GROUP BY 1,2;
-- ожидается пусто

-- 4. все шарды имеют ёмкость и живые ноды
SELECT c.env, c.plan, c.max_subscriptions FROM env_capacity c ORDER BY 1;
```

Если п.1 не нулевой — сначала добить перенос (ручной `POST /v1/access` по списку), а не удалять.

## 1. Выключить создание старого

| что | где | как |
|---|---|---|
| каталог продуктов | `config.toml` | удалить `enabled_conns`, `lite_enabled_conns`, `env_proto_templates` |
| активация по каталогу | роут `/v1/key/activate` | удалить роут и `ActivationFlow::Legacy` |
| трафиковый режим подписки | `[service] traffic_mode_enabled`, `metered_conns`, `subscriptions.limit_bytes` | выключить, лимит теперь в гранте |

После этого любая активация идёт через `/v1/activate`, состав прав — только `subscription_access`.

**Проверка:** активировать тестовый ключ через `/v1/activate` и убедиться, что в `connections`
появились только строки для vless/h2 (если они в гранте), а WG/AWG — нет.

---

## 2. Удалить код

### api

| файл / символ | что это | почему удаляем |
|---|---|---|
| `src/bin/api/entitlements.rs` (`ConnResolver`, `Product → env`) | резолв продукта в набор env/тегов | источник прав теперь `subscription_access` |
| `handlers/key.rs`: `ActivationFlow`, ветка `Legacy` | активация по каталогу | остаётся только грантовая |
| `handlers/connection.rs`: создание статических `Wireguard`/`AmneziaWg`/`AmneziaWgMobile` коннектов | серверные ключи для WG/AWG | пиры вместо них |
| `handlers/premium.rs`, `handlers/iap.rs`: те же ветки | выдача статики по продукту | IAP переводится на гранты |
| `tasks.rs`: реконсайлер по каталогу | дорисовывал коннекты из `enabled_conns` | заменяется EnsureFromGrants |
| `memory/connection/proto.rs`: `Proto::Wireguard`, `Proto::AmneziaWg`, `Proto::AmneziaWgMobile` | параметры статики | остаются `Xray`, `Hysteria2`, `Mtproto` — если mtproto ещё жив |
| `wireguard.rs`: `Keys`, `WgParam` (серверные ключи) | генерация серверной пары | приватных ключей на сервере больше нет |

### fnode

| что | где | комментарий |
|---|---|---|
| `[awg]`, `[wg]`, `[awg_mobile]` секции | `src/bin/node/config.rs`, `node-example.toml` | остаются `[awg_peers]`, `[wg_peers]`, `[xray]`, `[h2]` |
| `Tag::Wireguard`, `Tag::AmneziaWg`, `Tag::AmneziaWgMobile` | `src/memory/tag.rs` | **осторожно: rkyv-дискриминанты** — удалять только вместе с поднятием версии снапшота |
| ветки `apply` для статики | `src/bin/node/tasks.rs` | пиры идут через `apply_peer` |

Порядок безопасный: сначала перестать создавать (шаг 1), дождаться, пока на нодах не останется
статических пиров, и только потом удалять код. Иначе нода после обновления снимет рабочие пиры
человеку, которого ещё не перевели.

---

## 3. Удалить данные

Только после шага 2 и после того, как пройдёт хотя бы одна неделя без откатов.

| объект | что делать | риск |
|---|---|---|
| `connections` строки `wireguard`/`amnezia_wg`/`amnezia_wg_mobile` | `DELETE` | нет; но сначала проверить п.3 из раздела 0 |
| `connection_traffic` по этим коннектам | `DELETE` | историю трафика лучше оставить (квота), удалять только если не нужна |
| `connections` колонки `wg_pubkey`, `wg_privkey`, `wg_address` | удалить | после того, как ни одна строка их не использует |
| `keys.product` | оставить | ключи продаются и сейчас |
| view `subscription_traffic` | **оставить** | суммирует коннекты (vless/h2) и пиры |
| таблицы `peer_traffic`, `peers`, `devices`, `subscription_access` | основа, не трогать | |

`ALTER TYPE proto` — значения `wireguard`, `amnezia_wg`, `amnezia_wg_mobile` удалить нельзя без
пересоздания типа. Практично: оставить их «мёртвыми» — они никому не мешают, а пересоздание enum
на живой базе это отдельная операция с блокировкой.

---

## 4. Что остаётся навсегда (не удалять)

- **`connections`** — vless, hysteria2 (и mtproto, если ещё продаётся). Схема «сервер даёт ключ»
  для них не менялась.
- **`updates-<env>`** — топик для этих коннектов. Пир-топики (`peers-update-<env>`,
  `peers-init-<uuid>`) — отдельные.
- **`shares`** (шаринг доступа) — работает поверх коннектов, к пирам не относится.
- **`subscriptions`, `keys`** — продажа и сроки.
- **`subscription_traffic`** — единственный способ посчитать «сколько сожрала подписка» по обоим
  мирам.

---

## 5. Итоговый порядок

1. Все подписки на грантах (проверка 0.1).
2. Сайт и приложение работают только с `/v1/activate` и `/v1/peers` (неделя наблюдения).
3. Удалить каталог из конфига и роут `/v1/key/activate`.
4. Удалить код статики в api и fnode, обновить ноды (по одной).
5. Удалить строки/колонки статики из БД.
6. Обновить `AGENTS.md`/`HUMANS.md` и удалить из доков разделы про каталог; в спеке
   (`PEERS-SPEC.md`) отметить §2.4 «жизнь каталога» как выполненное.

## 6. Что может сломаться, если поспешить

- удалили код до переноса последних юзеров → у них пропали конфиги после обновления ноды;
- удалили `enabled_conns`, а IAP ещё продаёт старые продукты → покупка без выдачи;
- удалили колонки `wg_*`, а `GET /v1/config` ещё собирает конфиг по старым строкам → 500 на выдаче;
- снизили rkyv-версию снапшота без заголовка → нода прочитает старый файл мусором (у нас уже есть
  `FRKNSNAP` + версия, но вырезать enum-варианты можно только вместе с поднятием версии).
